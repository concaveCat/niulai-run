# EXP-006 按幅度缩放的轨迹

## Status

Testing：当前代码已加入按腿错峰的隔离舵机测试项目；软件串口验证完成，实体姿态和电源
边界仍待 Operator 观察。

## Objective

验证同一条轨迹能否在不改变方向、阶段时序和安全边界的前提下，以 `0..100%` 幅度
执行不同大小的动作，避免每次实验手工重写多个舵机脉宽。

## Hypothesis

将每个通道从直立位到当前候选目标的脉宽位移按百分比缩放，可以先用小幅度确认方向和
限位，再逐步扩大动作；相同的余弦平滑和阶段时间应保持动作连续性。该方法是脉宽
空间的实验工具，不等于已经完成足端笛卡尔轨迹或关节角标定。

## Hardware version

- ESP32-S3 N16R8；Carrier 映射 SDA=`GPIO11`、SCL=`GPIO12`、OE=`GPIO1`。
- PCA9685 地址 `0x40`、PWM 50 Hz；舵机电源为独立受控 6 V，共地。
- `step rf` 仅使用 CH0/CH1；`pose rest` 使用 CH0--CH7，CH8--CH15 保持 `FULL_OFF`。
- 实体动作前必须重新确认机械固定、运动限位、6 V 限流、人员净空和可立即断电急停。

## Software version

2026-09-12，分支 `fw/kw10-perfect-touchdown` 的未提交工作区；复现时记录实际
`git status`、构建镜像和烧录日志。

## Parameters

- 幅度档位：`0%/25%/50%/75%/100%`。
- `0%`：所有活动通道保持各自直立位；`step rf` 仍完成回直立并关闭 `/OE`，`pose rest`
  到达直立目标后保持输出，必须用 `stop` 收尾。
- `100%`：使用当前实验记录的完整候选目标。
- 中间档位：逐通道计算 `upright + (target - upright) * PCT / 100`，结果不能越过
  直立位与目标位之间的区间。
- `step rf` 总时长 1950 ms；当前 `pose rest` 是 400 ms 直立稳定加 2000 ms 进入目标的
  诊断路径。进入窗口按 CH0/1、CH2/3、CH4/5、CH6/7 四组依次执行 500 ms 余弦段，约
  2400 ms 到达目标后保持 `/OE LOW`，需要 `stop` 收尾；均使用 20 ms 更新周期。
- `pose rest` 的 6.5 s 保持/返回版本仍属于 EXP-005 的历史候选，不作为本实验的完成证据。

## Acceptance criteria

1. 无参数命令与 `100` 命令输出相同目标。
2. `0` 命令不改变直立脉宽；`25/50/75/100` 的每个通道都沿同一方向单调接近目标。
3. 所有幅度档位均保持当前阶段端点、`stop` 中止和 `/OE HIGH` 收尾语义；`step rf` 还必须
   完成回直立，`pose rest` 当前仅验证到目标并保持输出的探针；可选通道列表可用于单路/分组隔离。
4. 非法幅度（负数、超过 100、非整数或多余参数）被拒绝，不启动动作。
5. 在具备实体安全条件后，按从 25% 到 100% 的顺序逐档测试，记录实际方向、脚端
   是否拖地、限位、噪声、电流、温升和动作视频；任一异常立即停止，不进入下一档。

## Test method

1. 运行纯 C 数学测试和 `git diff --check`。
2. 完成 ESP-IDF build，确认启动时 PCA9685 `0x40` ACK、50 Hz 和 `/OE HIGH`。
3. 断开舵机 6 V 时先验证烧录和启动；实体测试先发送一次 `pose rest 25 CH0`，再使用
   `pose rest 100 0,1` 等分组命令，最后才运行默认 `pose rest 25/50/75/100`；每档结束
   明确发送 `stop` 并保存 UART 记录。
4. `step rf 25/50/75/100` 仅在右前腿单独固定且其他通道 `FULL_OFF` 时执行；每次完成或
   异常都确认 `/OE HIGH`。
5. 每个档位至少重复一次；如果观察结果不一致，保留失败记录，不从成功样本推断稳定性。

## Result

2026-09-12：`servo_zero_math.c` 与 `test_servo_zero_math.c` 以
`cc -std=c11 -Wall -Wextra -Werror` 编译并运行通过；覆盖 0/50/100% RF 目标、八路静息
目标的 0..100% 单调性、中间幅度取整和当前目标端点。`git diff --check` 通过。

同一工作区执行 ESP-IDF v5.5.5 `idf.py -B build-servo-zero build` 成功，镜像大小
`0x437e0`，app 分区余量 74%。固件命令入口已编译确认：`step rf [PCT]` 和
`pose rest [PCT] [CH[,CH...]]` 接受 `0..100` 和可选单路/逗号分组探针，省略幅度默认为
100%，非法幅度不启动动作。

先后完成烧录前构建元数据、USB/sysfs、串口占用检查；CH340 `1a86:55d3` 通过
`/dev/ttyACM0` 烧录三段镜像，均报告 `Hash of data verified`。启动日志确认 ESP32-S3、
PCA9685 `0x40` ACK、50 Hz、CH8--CH15 `FULL_OFF` 和 `/OE HIGH`。

底层对照：静态输出开启时重复写整帧 40 次无 NACK；CH0--CH7 单通道 100% 逐路到达目标；
前腿、后腿、全髋、全膝及两组对角四通道 100% 均到达目标。八路同步版本在 75% 三次均于
0.939--0.959 s 出现 `I2C hardware NACK`，100% 三次均于 0.559--1.109 s 出现 NACK；
故障时没有 ESP32 重启。该证据将故障范围收敛到多舵机同时运动的供电/公共地瞬态或机械
阻力，而不是 UART、烧录参数、PCA9685 地址或固定单通道。

归档的 Adafruit PCA9685 说明书没有记载“八路同步会导致 NACK”；相反，它说明板载 PWM
控制器可同时驱动 16 路，并警告多舵机同时运动的电流、噪声和棕断风险，建议电源下陷时从
`n×100 uF` 估算附加电容。因此本文将 NACK 记为本机实测表现，不将它写成 PCA9685 的
通道协议限制；`SERVO_6V` 压降、公共地、bulk 电容、I²C 上拉和机械阻力仍需台架测量。

将默认轨迹改为四条腿依次、每条腿髋膝两路同步的 250 ms 余弦段后，连续 5 次 100% 默认
`pose rest` 均输出 `rest pose reached`，未见 NACK；每次均以 `stop` 收尾。该结果证明
软件错峰和故障安全路径稳定，但不等于实体方向、限位、电源压降、电流、噪声或温升已验收。
