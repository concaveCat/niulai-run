# EXP-005 静息站立姿态

## Objective

验证四条腿能从已确认的垂直直立位平滑进入一个静息站立候选姿态，并在目标位保持供
Operator 观察；本实验的收尾由 UART `stop` 关闭 PCA9685 `/OE`，不把自动返回误当作
动作验收条件。

## Hypothesis

四个髋关节按 Operator 当前确认的方向，四个膝关节按前/后腿实际折叠方向补偿，可以形成
比全腿垂直更自然的静息站立姿态。当前只验证从已确认直立中立位平滑进入 Operator 实测
目标；这里不把通用脉宽换算当作实际关节角标定。

## Hardware version

- ESP32-S3 N16R8；Carrier Gerber 映射 SDA=GPIO11、SCL=GPIO12、OE=GPIO1。
- PCA9685 地址 `0x40`、PWM 50 Hz；舵机电源为独立受控 6 V，共地。
- CH0--CH7 对应 RF hip/knee、LF hip/knee、RR hip/knee、LR hip/knee；CH8--CH15
  保持 `FULL_OFF`。
- 实体测试前须确认机械固定、限流、人员净空和可立即断开 6 V 的急停方式。

## Software commit

2026-09-12 基于分支 `fw/kw10-perfect-touchdown` 的未提交工作区实现；复现时以实际
`git status` 和固件启动日志中的 app version 为准。

- 脉宽幅度：CH0--CH7 使用 Operator 实测静息目标
  `1494/1165/1672/1748/1368/1279/1764/1934 us`；前腿不使用此前导致扒地的镜像目标。
- 时间线：直立稳定 400 ms；随后 CH0/1、CH2/3、CH4/5、CH6/7 四组各用 500 ms 余弦
  平滑段，进入窗口总计 2000 ms，从命令开始约 2400 ms 到达目标；抵达目标后保持，需 `stop` 收尾。
- 更新周期：20 ms；每个通道使用余弦半波，起止速度为零；最多两路同时改变。
- 已记录的髋关节候选止挡 CH0/2/4/6=`1400/1750/1940/1120 us` 现由 Operator 确认方向为：
  CH0/CH2 前腿向后，CH4/CH6 后腿向前。由于四个舵机安装零位不同，这四个值只在各自
  通道上生效，不能互相复制或转换成统一髋关节限位；四个膝通道没有已知机械止挡。

## Acceptance criteria

1. 启动保持 `/OE HIGH`；只有明确的 `pose rest` 才执行一次姿态预览。
2. 动作前先在 `/OE HIGH` 预载八路直立值；动作期间 CH8--CH15 保持 `FULL_OFF`。
3. CH0--CH7 以 20 ms 周期按四组错峰时间线运动，在 2.0 s 进入窗口内到达目标并保持；
   `stop` 后恢复八路直立值并自动 `/OE HIGH`。
4. UART `stop` 可中止姿态并立即拉高 `/OE`；任一 I2C 错误同样停止输出。
5. 固件 host 测试验证所有阶段端点、目标值、完成状态和已记录髋止挡余量。
6. 实体观察无撞限位、明显抖动、异常噪声、过流或快速温升；四髋方向及前/后腿膝折叠
   方向由 Operator 逐腿确认。

## Test method

1. 先运行 host 数学测试和 ESP-IDF 构建；按仓库烧录流程检查构建元数据、USB 三层、
   串口占用和启动日志。
2. 确认机器人可靠固定、6 V 限流、人员净空和急停可用；从 `/OE HIGH` 发送一次
   `pose rest`。
3. 同步观察四髋方向、四膝方向、机身高度、足端是否滑动、供电电流、异常噪声和温升。
4. 任一腿方向错误、接近止挡或出现异常时立即发送 `stop` 并切断 6 V。
5. 保存 UART 证据；物理结果必须由 Operator 观察后填写，不能从 UART 推断。

## Result

### 历史版本结果（已被后续目标和轨迹取代）

2026-09-12：已实现 `pose rest` 的八路 20 ms 轨迹任务、动作互斥、UART `stop` 中止、
I2C 失败禁能和完成后恢复直立 `/OE HIGH`。纯 C 测试以
`cc -std=c11 -Wall -Wextra -Werror` 编译并通过，覆盖八路目标、阶段端点、完成状态和四个
已记录髋止挡候选余量；`git diff --check` 通过。ESP-IDF v5.5.5
`idf.py -B build-servo-zero build` 成功，镜像为 `0x41060` 字节，app 分区余量 75%。

烧录前检查确认 CH340 `1a86:55d3`、sysfs `ttyACM0` 和 `/dev/ttyACM0` 均可见；发现上一轮
串口采集脚本 PID 403262 遗留占用端口，确认来源后发送 SIGTERM，随后 `fuser` 确认
端口空闲。按 `flasher_args.json` 烧录 bootloader、app 和 partition table，三段均报告
`Hash of data verified` 并硬复位。启动日志确认 app ELF SHA256 `aae2a3af2...`、PCA9685
`0x40` ACK、50 Hz、CH8--CH15 `FULL_OFF` 和 `/OE HIGH`。

Operator 已明确确认机械固定、6 V 限流、运动区域净空和可立即断电急停四项条件，并执行
一次 `pose rest`。UART 显示目标髋为 `1636/1537/1729/1339 us`、目标膝为
`1359/1525/1692/1490 us`，`6500 ms` 后回到直立并输出
`rest pose complete; upright restored; /OE HIGH`，随后兜底 `stop` 也显示 `/OE HIGH`。
这证明命令到达、轨迹任务完成和故障安全关断路径工作；尚未记录 Operator 对实际四髋/四膝
方向、机身姿态、足端滑动、限位、电流、噪声或温升的观察，因此实体姿态验收仍未完成。

Operator 随后报告计时版姿态“腿仍然垂直、没有动作变化”。为区分进入速度和目标幅度，
又执行了一次无渐变直达目标测试：八路直接写入同一组静息目标，`run -> /OE LOW` 保持约
3 s，再 `stop -> /OE HIGH`；UART 无 I2C 错误。此前同一固件下 CH0 `1746→1600 us` 已
被 Operator 确认能动作，因此当前更像是静息目标幅度/通道方向与装配姿态不匹配，而不是
UART、PCA9685 或全局舵机供电链路故障；直达测试的现场结果仍待 Operator 观察。

根据 Operator 的进一步观察，后腿髋 CH4/CH6 的摆动方向也与第一轮假设相反；第二轮已将
CH4/CH6 改为 `1399/1669 us`，并保留后膝 CH5/CH7 的反转方向，同时把全部目标位移加倍
到 `220 us`。本轮已重新通过 ESP-IDF v5.5.5 构建并烧录；启动日志确认 `/OE HIGH`、
PCA9685 `0x40` ACK 和 50 Hz。

烧录后先执行后髋方向探针：CH0/1/2/3/5/7 保持直立值，CH4=`1509 us`、CH6=`1559 us`，
输出约 2.5 s；脚本正常结束后发送 `stop`，恢复并保存八路直立值。探针的实体摆动方向、
限位、电流、噪声和温升尚未由 Operator 回报；本次串口脚本输出未落盘，命令参数如上。

### 当前目标与底层排障结果

Operator 随后提供了实际观察到的静息姿态脉宽：`1494,1165,1672,1748,1368,1279,1764,1934 us`。
该组值取代此前候选，作为当前平滑进入目标。

随后提出的前腿镜像目标 `1998,1773,1182,1082,1368,1279,1764,1934 us` 已被 Operator
确认会导致前腿扒地，因此标记为 `Superseded`，当前代码恢复为上表的实测方向。

本轮底层排障结果：静态整帧 I²C 重写 40 次无错误；CH0--CH7 单通道 100% 逐路到达目标；
前腿、后腿、四髋、四膝四通道分组以及两组对角四通道分组均到达目标。八路同步运动则在
75% 三次均于 0.939--0.959 s 出现 PCA9685 hardware NACK，100% 三次也于 0.559--1.109 s
出现 NACK；故障时 ESP32 没有重启，固件按设计将 `/OE` 拉高。该模式将根因范围收敛到
多舵机同时运动的供电/公共地瞬态或机械阻力，而不是 UART、烧录参数、PCA9685 地址或单个
PWM 通道。无限总线复位重试已移除，避免先前的 WDT；当前错误路径为单次失败即安全停机。

当前软件候选将默认动作改为四条腿依次、每条腿髋膝两路同步的 500 ms 余弦段，总进入窗口
为 2.0 s（另有 400 ms 直立稳定，总计约 2.4 s）。此前 250 ms 候选连续 5 次串口驱动动作均输出
`rest pose reached`，未见 NACK；每次均发送 `stop` 收尾。该 UART 结果证明软件动作和总线
保护路径稳定，但四髋/四膝的实际方向、姿态、足端滑动、限位、6 V 电流、电源压降、噪声
和温升仍必须由 Operator 观察，不能仅凭日志完成机械验收。
