# GAMEPLAY_DESIGN_v0.1 — 软件玩法开发 Prompt

Status: **Proposed**

Last reviewed: 2026-09-09

## 任务

为牛来快跑设计并实现一个舒适、可复盘的玩法闭环。核心体验是：玩家亲自协调四条腿；系统只记录、反馈和评分，不替玩家规划步态。

优先在 Android `Test Ctrl` 中完成可测试原型，再接入真实 FSM、触地和赛道数据。

## 用户流程

```text
Main → Connect/Test → 简短教学 → Play → Result → Rematch
```

- 首次进入 Ctrl 时展示一次 press → hold → release 教学；之后可跳过。
- Play 页面优先保留四个大触控区，只显示计时、连接/安全状态和必要反馈。
- Result 页面并列显示速度分和人类协调分，并显示用时和迈出的步数。
- Rematch 保留当前模式和配置，一步重新开始；应用不提供事件回放页面。

## 双评分

### 速度分

评分单位是“有效步”，不是按键变化。Test 模式把每条腿的模拟按下—松开作为
可重复的 mock 有效步；实体模式必须由 STATUS 的 `appliedLegMask`、离地/触地
变化和释放顺序确认完整动作。当前 Android-only 候选公式为：

```text
速度分 = 70% 有效步节奏 + 20% 连贯性 + 10% 有效步数量
```

少于 3 个有效步显示“试跑数据”，不输出正式分数；没有实体触地确认时不伪造
实体进度。摔倒失败固定为速度分 0。

### 人类协调分

使用输入和状态事件评价：

- 操作是否清晰，是否存在抖动或无效重复输入；
- 保持时间和动作间隔是否逐渐稳定；
- STATUS 是否确认应用、离地和重新触地；
- SEARCH 是否成功触地、是否超时；
- 失败后是否由玩家主动完成恢复。

当前 Android-only 候选公式为：

```text
协调分 = 40% 动作完成率 + 25% 固件接纳率 +
         20% 节奏稳定性 + 15% 四腿参与度
```

该方案不要求复制唯一 gait；交叉腿、同侧腿或不同节奏都可以，只评价动作是否
被接纳、是否完成和是否稳定。摔倒失败固定为协调分 0。

评分不得要求玩家复制唯一标准 gait。公式、权重和阈值必须集中配置，并等待 mock 与实体实验校准。Play 中不实时展示协调分，避免干扰操作或诱导刷分。

## 赛后记录

- 保存单调时间戳、输入 mask、腿状态、contact、checkpoint、FAULT、failsafe 和会话配置。
- 同一事件记录必须能重算出相同结果。
- 诊断建议必须能指向记录中的具体事件，不生成没有证据的结论。
- 事件记录仅用于评分和生成评价，不提供事件回放界面。

## 音频反馈

使用短促、可区分的事件音提示 LIFT、contact、失败和 failsafe。默认避免持续循环音；重复事件需要节流。所有关键信息必须同时有视觉反馈，并提供静音选项。

## 多人模式

第一阶段只实现单设备双人分区：玩家 A 控制 FL/RL，玩家 B 控制 FR/RR。双方输入合并为完整 mask，但系统不得补全或预测任何腿输入。多设备同步和多个 BLE Central 不在本轮范围。

## 软件边界

玩法层作为现有控制边界之外的观察者和会话管理器：

```text
PlayerInput → existing control boundary
      └────→ GameplaySession → Scoring / Feedback
```

- 不修改 `CONTROL_SPEC_v0` 的状态语义。
- 不自动选腿、生成 gait、补步或恢复平衡。
- 不让评分、音频或多人模块直接调用执行器。
- 不改变 `BLE_PROTOCOL.md`；缺少遥测时通过可替换事件源降级。
- 断连、FAULT 和 failsafe 的显示优先于所有游戏反馈。

## 本轮交付

实现一个 Test Ctrl 最小闭环：

1. 开始和结束一局；
2. 记录四腿输入事件；
3. 使用明确标注的 mock 状态/contact/进度计算双评分；
4. 播放可静音的事件音；
5. 展示 Result 和 Rematch；
6. 提供单设备双人左右分区模式；
7. 为事件记录、评分确定性和页面流程增加测试。

不要在本轮实现实体舵机控制、真实多人网络、视觉导航、排行榜服务或完整关卡系统。

## 验收条件

- 新玩家能通过简短教学完成一次操作。
- Play 页不缩小或遮挡现有四腿触控区。
- 速度分与协调分来源可解释；缺失数据不被伪造。
- 结算页显示双评分、用时、步数和 AI 评价正文，不单独展示优点/建议卡片。
- 评分和音频对控制输出均为只读。
- 静音后玩法完整可用。
- 断连、FAULT、failsafe 能立即中止会话反馈并明确显示。
- 现有 Android、BLE 和 firmware mock 测试继续通过。

## 后续验证后再决定

实体数据接入、评分权重、音频输出位置、多设备协作、checkpoint 检测和正式关卡均保持开放，不因本 Prompt 自动冻结。
